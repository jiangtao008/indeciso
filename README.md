# 别纠结 · Indeciso

> 别纠结，让选择变简单。
> Stop Overthinking. Start Choosing.

一个完整的个性化随机决策 Web 应用：用户自建候选项（文字 / 图片 / 组合、权重、分类），系统用密码学安全的随机算法做出选择，并用沉浸式动画揭晓结果，全程保存可回溯的历史快照。

实现覆盖 `需求文档.md`（V1.0）与 `需求文档V1.1.md`（新增：多选择池、权重随机、最近结果排除、单项重抽、三种随机模式、9:16 分享卡片、模板库）。

---

## 一、技术选型：Python 还是 JavaScript？

**结论：TypeScript 全栈。**

| 维度 | Python（FastAPI / Django） | JS / TS（Node） |
|---|---|---|
| 前端动画、3D 卡片、Canvas 分享图 | 前端仍必须用 JS，形成双语言 | 前后端同语言 |
| 本项目后端负载 | 认证、CRUD、SQLite、文件上传、加权抽样：纯 I/O，用不上 Python 的算力生态 | 同样胜任 |
| 代码复用 | 随机规则、CSV 解析、数据类型要在两端各写一遍，容易漂移 | 同一份 `shared/` 类型与 CSV 解析器直接复用 |
| 交付与部署 | 两套运行时、两套依赖 | 单仓库、单命令、单进程 |
| Python 的真正优势（数据 / ML / 重图像处理） | V2 的 AI 能力是调用模型 API，不需要本地 Python | 不构成劣势 |

最终技术栈：

- **前端**：React 19 + Vite 8 + TypeScript + Tailwind CSS v4 + 原生 CSS 动画 / requestAnimationFrame
- **后端**：Node.js + Express 5 + Node 内置 `node:sqlite`（零原生依赖）
- **校验**：Zod
- **上传**：Multer（内存处理 + 魔数校验 + 按用户落盘）
- **随机**：`node:crypto` 密码学随机源，服务端不放回加权抽样
- **分享图**：Canvas 2D 独立绘制 1080 × 1920，不截屏

> 如果未来需要离线跑模型、做大规模推荐或复杂图像处理，可以独立拆出一个 Python 服务；当前 V1.0 没有任何场景需要它。

## 二、快速开始

环境要求：**Node.js ≥ 22.12**（依赖内置 `node:sqlite`），已在 Node 26 上验证。

```bash
npm install
npm run dev
```

打开 <http://localhost:5173>。

- 体验账号：`demo` / `demo1234`（首次启动自动创建，自带「今天吃什么」「周末去哪玩」两个选择池）
- 也可以直接注册新账号，系统会自动创建一个空选择池

生产模式：

```bash
npm run build     # 构建 web/dist + dist-server/index.cjs
npm start         # http://localhost:8787
```

环境变量（可复制 `.env.example` 为 `.env`，开发与生产启动都会自动读取）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `8787` | API / 生产网页端口 |
| `COOKIE_SECURE` | `false` | 部署在 HTTPS 后设为 `true` |
| `SEED_DEMO` | `true` | 是否自动创建 demo 体验账号，正式部署建议 `false` |

数据保存在本地 `data/`：

```text
data/
├── indeciso.db        # SQLite（用户、选择池、选择项、随机记录、历史快照）
└── uploads/<userId>/  # 按用户隔离的图片
```

删除 `data/` 即可获得一份干净的全新环境（下次启动会重新创建 demo 数据）。

## 三、功能清单

### 用户与安全
- 注册 / 登录 / 退出，用户名唯一（大小写不敏感），密码使用 **scrypt + 随机盐** 哈希
- HttpOnly + SameSite=Lax 会话 Cookie，30 天持久化，服务端会话表可撤销
- 登录频率限制、参数校验、统一错误文案
- 所有业务接口强制鉴权；选择池、选择项、历史、图片按用户隔离（已用跨账号请求验证）
- 图片上传限制 PNG / JPG / WebP、8MB、魔数嗅探；图片通过鉴权路由按用户访问

### 选择池（V1.1）
- 创建 / 重命名 / 描述 / 删除（二次确认）/ 复制（不含历史）/ 切换 / 设为默认
- 每个池独立的候选项、随机配置与历史关联；历史按池筛选
- 删除池不删除历史，快照仍可查看

### 选择项管理
- 文字、图片、文字 + 图片；权重（> 0，最多两位小数）、分类、标签、收藏
- 双模式编辑：**表格**（内联编辑、图片上传/替换/删除、权重、拖拽排序、上移/下移、删除确认、批量添加）与 **CSV 文本编辑器**
  - 两侧共用同一份数据模型，任一侧修改都会同步
  - 完整 CSV 解析：引号、字段内逗号、转义引号、空字段、空行、BOM、CRLF、表头重排、未知扩展列向后兼容
  - 语法高亮、行号、错误行定位与跳转
  - 文本解析失败不覆盖表格数据，并禁用保存
  - 表格编辑覆盖了有错误的文本时，会明确提示
  - 未保存修改离开浏览器有提醒，可一键放弃
- 至少一个有效选择项才能抽取；每次保存后自动收敛非法的结果数量

### 首页与随机
- 品牌导航、选择池切换、历史/设置入口、用户菜单、深/浅色主题
- 漂浮卡片：自然漂浮、水平/垂直移动、轻微旋转、缩放、视差、鼠标靠近位移、悬停放大；移动端使用左右栏位布局避免拥挤
- 大尺寸品牌按钮、按状态切换的趣味文案（避免连续重复）
- 三种随机模式，共用同一份服务端随机结果：
  - **直接揭晓**：加速漂浮 + 命运滚动词 + 逐个揭晓
  - **命运转盘**：SVG 转盘，扇区按权重分配面积，先算结果再旋转，最终停在目标扇区
  - **淘汰模式**：多轮淘汰动画，最终幸存者严格等于预先算出的结果
- 多结果按配置间隔依次揭晓，已揭晓结果保留；结果卡逐个独立动画
- 单项重抽：只替换指定位置，不与本轮其他结果重复，尽量避开被替换的旧项
- 结果数、间隔、动画速度、模式、最近 N 轮排除均为池级配置并持久化
- 随机过程中按钮不可用；动画开始前结果已确定且全程不变

### 历史记录
- 完整完成的随机自动保存为**一条**记录（多结果不拆分），写入幂等
- 保存完整结果快照（标题 + 图片），之后修改/删除选择项或选择池都不会影响历史展示
- 倒序列表、分页加载、按池筛选、详情弹层、删除单条、清空（二次确认）
- 历史详情可重新生成分享卡片
- 中断的随机（动画未完成、页面关闭）不会写入历史，也不会参与「最近结果排除」

### 分享卡片
- 1080 × 1920、9:16、PNG，独立 Canvas 渲染（不是截屏）
- 品牌标识、选择池名称、结果、趣味文案、Slogan、日期
- 结果数量自适应布局（1 个大卡 / 2–3 行卡 / 4–6 网格），超过 6 个显示「还有 N 个」
- 预览、保存图片、系统分享（不支持时回退下载）、复制结果文字
- 分享图不含账号、头像等个人信息

### 模板库
- 6 个预置场景：今天吃什么 / 喝什么 / 周末去哪玩 / 今天看什么 / 今天做什么 / 聚会玩什么
- 浏览、预览全部候选项、新建池或追加到当前池、重复项去重开关、确认后批量导入
- 导入的是用户自己的副本，公共模板不被修改

### 趣味与品牌
- 统一文案池：首页、随机中、结果、重抽、空状态、错误提示分别有独立文案
- 品牌吉祥物作为 Logo、头像、空状态与加载状态视觉
- 深色 / 浅色主题，遵循 `prefers-reduced-motion`，键盘焦点可见

## 五、关键设计

### 1. 随机与动画彻底分离
1. 点击按钮 → `POST /api/pools/:id/draw`
2. 服务端从有效候选项中**不放回加权抽样**，结果写入 `draws` 表（`pending`）
3. 前端拿到已经确定的结果，动画只负责播放；所有模式读取同一份结果
4. 所有结果揭晓完成后 → `POST /api/draws/:id/complete`
5. 服务端把该轮最终结果快照写入 `history`，并把 draw 标记为 `completed`（重复调用幂等）

因此：
- 转盘停在哪、淘汰谁，都无法反向影响结果
- 动画中途关闭页面不会留下「成功历史」
- 单项重抽更新的是同一个 pending draw / 同一条历史，不会新增记录

### 2. 最近结果排除
按池读取最近 N 条**已完成**历史的 itemId 去重集合，先排除，再对剩余项按权重抽样。排除后不足时返回明确错误码（`INSUFFICIENT_ITEMS`），不会静默放宽规则。单项重抽时还会额外排除本轮其他结果，并尽量避开被替换的旧项。

### 3. 权重
权重只影响抽样概率：每抽出一个候选项，就把它移出本轮池，再按剩余权重重新计算下一次概率（不放回加权抽样）。排序不改变权重，权重也不改变展示顺序。

### 4. 历史快照
`history.results_snapshot` 保存 `item_id / title / image_url / sort_order`，读历史时**不**回查当前选择项。图片文件不会在删除选择项时清理，保证旧记录仍能展示。

### 5. 双模式编辑
`shared/csv.ts` 是前后端共用的解析器。前端只维护一个 `EditableItem[]` 模型：
- 表格修改 → 更新模型 → 重新生成文本
- 文本修改 → 解析 → 校验 → 更新模型（失败则保留原模型并禁用保存）
- 保存时一次性 `PUT /items`，服务端按 `id` 增删改并重排 `sort_order`

### 6. 安全与数据边界
- SQL 全部参数化
- 密码 scrypt（N=16384, r=8, p=1）+ 随机盐 + `timingSafeEqual`
- 上传文件名服务端生成，访问时校验登录用户与路径归属
- 前端渲染全部经过 React 转义；分享图只加载同源图片，避免 canvas 污染

## 六、接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` / `login` / `logout` | 注册 / 登录 / 退出 |
| GET | `/api/auth/me` | 当前用户 + 设置 + 选择池列表（bootstrap） |
| GET/POST | `/api/pools` | 列出 / 创建选择池 |
| GET/PATCH/DELETE | `/api/pools/:id` | 详情 / 修改 / 删除（含自动兜底默认池） |
| POST | `/api/pools/:id/default` / `copy` | 设为默认 / 复制 |
| PUT | `/api/pools/:id/items` | 整体保存选择项（统一数据模型） |
| PUT | `/api/pools/:id/settings` | 保存池级随机配置 |
| POST | `/api/pools/:id/draw` | 生成随机结果（pending draw） |
| POST | `/api/draws/:id/redraw` | 单项重抽 |
| POST | `/api/draws/:id/complete` | 完成并幂等写入历史 |
| GET/DELETE | `/api/history` | 分页列表 / 清空（可按池） |
| GET/DELETE | `/api/history/:id` | 详情 / 删除单条 |
| GET | `/api/templates` | 模板列表 |
| POST | `/api/templates/:id/import` | 新建池导入 / 追加到已有池 |
| POST | `/api/uploads` | 上传图片，返回稳定 URL |
| GET | `/uploads/:userId/:file` | 鉴权图片访问 |
| GET/PATCH | `/api/settings` | 全局偏好（主题、当前池） |

统一错误格式：

```json
{ "error": { "code": "INSUFFICIENT_ITEMS", "message": "……", "details": { "available": 2, "requested": 3 } } }
```

## 八、已知边界与后续版本

本期未实现（与 PRD 的版本规划一致）：

- 音效系统、吉祥物多表情动画（V1.0 允许预留）
- 分享卡片多主题（当前为一套品牌默认主题，渲染层已按参数化组织，便于扩展）
- 模板包含图片素材、用户自定义模板与模板市场
- 历史搜索、筛选、多设备实时同步
- 未保存修改在「切换选择池 / SPA 内部跳转」时的全局拦截（浏览器关闭有 `beforeunload` 提醒，编辑区有明确提示与放弃入口）
- AI 生成选择项与图片（V2.0）

生产部署建议：

- 使用 HTTPS，并设置 `COOKIE_SECURE=true`
- 设置 `SEED_DEMO=false`
- 定期备份 `data/`（SQLite 开启 WAL，可在线备份）
- 单实例部署；若要多实例，需要把 SQLite 换成 PostgreSQL 并共享图片存储
- 注册接口暂无验证码/邮箱验证，公开部署前建议补充
